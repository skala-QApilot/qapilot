## 지시사항

1. **FR 1개 = TS 1개**를 기본 원칙으로 한다. 각 요구사항을 별도 TS로 만들어라.
2. 예외: 동일 리소스의 목록 조회와 상세 조회처럼 같은 객체를 읽는 방식의 차이만 있는 경우에만 묶을 수 있다.
3. 서로 다른 동사(생성/수정/삭제/조회)를 가진 요구사항은 같은 도메인이라도 반드시 분리하라.
   - 예: 회원가입(FR-AUTH-01), 로그인(FR-AUTH-02), 프로필 조회(FR-AUTH-03)는 각각 별도 TS
4. 각 TS에 대해 name, description, domain_area, requirements를 작성하라. TC는 생성하지 말 것.
5. TS 이름과 설명은 **반드시 한국어**로 작성하라.
6. requirements 필드에는 위 목록에 실제로 나열된 요구사항 ID만 넣어라. 없는 ID를 만들지 마라.
7. JSON만 출력하라. 마크다운 코드블록이나 설명 텍스트를 포함하지 마라.
